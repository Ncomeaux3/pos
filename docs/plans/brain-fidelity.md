# Second Brain to the artboard

Superseded for styling on 2026-09-19 by the Holon redesign (docs/plans/holon-product-redesign.md, section 4): colour, type, radii, surfaces and control shapes now come from the Holon design contract and the shared components in `components/pos/`. This plan still governs what each screen shows and how it is laid out.


## Context

Screen seven of the fidelity pass (method: docs/plans/weekly-review-fidelity.md). `POS Second Brain.dc.html` captured at 1440 (38 PNGs: inbox, inbox editing, a video and a book draft, notes, notes editing, reading list with a book to finish and a finished one, every folder, search hits and no hits, the ingest drawer in its four kinds and running, the inbox after an ingest and empty, dark and light) into `/private/tmp/pos-handoff-sources/brain/`. The app has the right data (drafts beside their source, `[[wikilinks]]` both ways, dangling links kept, the vault pulled read only, ingest guarded) under a screen of another shape: a title block and lede, underlined TabBar folders, a paste-a-link row on the inbox and a title-then-Enter row on Notes, `Row` list rows with chips, a card stack on the right with a textarea that saves on blur, an "As prose" preview, a "Links" card, a page-level "Links with nothing behind them" card, and "Send back to the inbox".

The artboard: the 56px band (crumb "Second Brain / {Inbox | Reading list | folder}", the scoped search, "{n} notes" with a dot, "Ingest →" as the DS button); a folder row of filled chips on `--bg-elev` (Inbox with an amber count, Reading list, then the seven folders) with "Vault in git is the source of truth" on the right; a two-pane body, list 280 to 380 with its own head and rows (title, when, sub, KIND, DRAFT), and the note pane. A draft shows an amber eyebrow, Discard / Edit / "Commit to vault →", then Source and Draft summary side by side with skills under the draft. A note shows "{folder} / {slug}.md", the title, Mark finished or FINISHED, Edit and "Save · commit", the body as paragraphs, lists and accent links, then Linked skills, Backlinks and Commits cells. A 480px Ingest drawer with URL, YouTube, Book and PDF, Folder and Depth, a running box, and "Draft summary →".

Decisions with Nick (append to `decisions/log.md`):
- The title block and lede go; the band, the folder row and the two panes fill the page as drawn (page scrolls as a whole; the panes are not independently scrolling regions, which would fight the sync banner's height). The h1 stays `sr-only`.
- Folder chips replace the TabBar: filled chips as the artboard draws them, built inline in the module (no shared change; PillGroup is a different shape). All nine cells always show, counts included at zero. Reading list is articles plus books in any status; its meta counts finished ones.
- Search: the band's search stays the shared piece (opens the palette, placeholder "Search second brain"). The in-list results with score bars, "{n} · semantic" and the "Vector search covers meaning" copy are not built: `core/search.ts` is hybrid (words first, Voyage only when words find nothing), so the copy would be true, but a second query box breaks the one-query rule BandSearch states. Alternative if wanted: `?q=` runs `search(q, { module: 'brain' })` server-side with the meta saying "words" or "meaning" by the mode.
- Nothing writes to the vault, so: the draft primary reads "Accept →" not "Commit to vault →"; the draft sub-line reads "{source} · will file under {folder} / {slug}" (no `.md`, no `vault/`); "Save · commit" reads "Save"; the Commits cell becomes "Vault": a pulled note shows its vault path, short blob sha and when it was pulled, any other note reads "Not in the vault. Nothing here writes to it."
- Discard is a new `delete` tool, guarded like Tasks and Travel, behind `confirm()`, offered on drafts only as drawn.
- Nick, 2026-09-11: adding a book or an article to Second Brain means he finished it. No `finished_at` column, no `finish` tool, no migration, no "Mark finished" button. Accepting a book draft keeps emitting `book_finished` as today; accepting an article draft emits `article_read`, which already has a weight (5) in `modules/skills/xp.yaml`; no new weight, no migration, no edit under `modules/skills`. `publish` also emits `note_approved` for every kind. The Reading list is every accepted book and article, each row and the note head showing "FINISHED · {accepted date}" (mono 10px green, the date from `updated_at` of the published note).
- Skills chips and the RULES · MODEL · MANUAL by-line come from `core.skill_links` through the `skillNames` seam the Tasks session is landing (plan assumes it is committed first). Chips link to `/skills?skill={id}`. "Nothing matched yet." when empty.
- The Draft summary meta reads "HAIKU · {n} WORDS" when the draft has a `source_url` (ingest is the only path that drafts with Haiku) and "{n} WORDS" otherwise; a draft whose summary the cap stopped shows the ingest's own note where the body would be.
- Ingest drawer: 480px (`narrow`), `?ingest=1` in the URL. Kinds URL, YouTube, Book, Note; PDF is not built (no extractor, no dependency, Node runtime). Depth and the prices are not drawn (one Haiku call, no deep mode). Folder select stays: `ingest` gains an optional `kind`. Book and Note write a published note through `write` (title, your notes as the body, no model call); the footer line says which of the two things will happen for the picked kind. The running box is one line, "Reading, drafting, classifying · a few seconds", with the accent dot: the ingest is one call with no progress events, so four ticking steps would be theatre.
- Edit is offered on every note except one pulled from the vault (`source = 'vault'`): its file is the truth and the next pull would rewrite it. Those show "A file in the vault. Edit it there." in the button's place.
- Gone because the artboard does not draw them: "Send back to the inbox" (the tool keeps its `publish: false` half), the title-then-Enter row (the drawer's Note kind covers it), the page-level "Links with nothing behind them" card and the band's "{n} links to write". A note's own unresolved links become a fourth cell, "Links to write", in the note grid (the grid is auto-fit, so a fourth cell sits naturally) with the existing start-from-link buttons.
- List row copy the app cannot produce ("6 min", "Kleppmann · reading · ch. 5 of 12", "transcript via yt-dlp"): the sub-line is "{host of source_url | vault folder | kind} · {n} words"; `when` is days since `updated_at`.
- When the URL names no note the pane shows the first row of the list (the artboard's behaviour); "Select a note" appears only when the list is empty.
- The body renderer follows the artboard's three rules only (paragraphs on blank lines, `- ` and `1. ` lines as a list, `[[x]]` as an accent link that opens the note; an unresolved link renders as plain accent text). Headings and the rest of markdown stay plain text, marked `ponytail:`.
- Phone: no phone layout exists for this screen; the panes stack, checked against the shell rules only.
