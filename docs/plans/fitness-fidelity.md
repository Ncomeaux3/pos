# Fitness to the artboard

## Context

Screen eleven of the fidelity pass (method: docs/plans/weekly-review-fidelity.md). `POS Fitness.dc.html` captured at 1440x900 into `/private/tmp/pos-handoff-sources/fitness/` (setup idle, Strava authorising, Strava connected, Apple Health enabled, importing, live; dark and light, 12 PNGs). The artboard is a three-state screen: a "Connect a workout source" card on a hairline grid (Strava OAuth row, Apple Health webhook row, "Run first import"), an importing screen with four steps and a bar, and a live overview (band with "Strava · synced just now", title block with a mono "212 WORKOUTS · 2019 → TODAY" on the right, four tiles at 34px, one "Recent workouts" card with a five column table: DATE, WORKOUT, TIME, SKILL, XP). The app already has the band with the shared SyncBand, a title block, a four tile strip and the workout list, plus four URL tabs (Workouts, Exercises, Body, Plan) the artboard does not draw, the plan cards and the coach card, a Load tile and a Heaviest set tile. What differs on the live screen: the band's crumb (the app writes the week's count as the crumb), the lede, the right hand mono line, the tiles (the artboard's This week reads "3 workouts" with "2H 41M · +36 XP HEALTH" under it, a named lift's best set with when it happened, a goal tile in the goal's status colour, a Body metrics tile), and the list (the artboard is a headed table inside a card, the app is a RowList with a brand chip per best set). Two things the artboard draws that the app cannot produce as written: an XP figure per workout (the weight lives in `skills.xp_weight`, which Fitness cannot read; nothing in core knows it) and Apple Health body metrics (the Health Auto Export webhook is a validated no-op in `integrations/health_auto_export/manifest.ts`; nothing writes `fitness.body_metric` from it). The artboard's importing screen has four steps with counts the app's single `sync_strava` job does not report. The fixture has no Strava connection and ten hand-logged workouts, a state the artboard never draws (its empty state assumes no data, its live state assumes Strava).

Decisions with Nick (append to `decisions/log.md`):
- Which state the page draws: the artboard's setup card is a wall and the app's rule (`app/(app)/[module]/[[...path]]/page.tsx`) is a banner, not a wall. Default: the live layout whenever at least one workout exists, whatever the source; the setup card only when there are no workouts at all. With no workouts and Strava connected the card shows the connected row and "Run first import →" (runs `syncFitness`, the same job as Sync now). The shared "Not syncing" banner above stays as it is (app/*). Band crumb "Fitness / Overview" or "Fitness / Setup"; the right hand status stays the shared SyncBand ("Strava · not connected", "never synced", "synced 04:02"), not the artboard's "Strava connected · not imported".
- Apple Health: the webhook accepts and validates Health Auto Export payloads and writes nothing (`integrations/health_auto_export/manifest.ts`, `webhook: async () => {}`), so "Fitness reads body metrics from Apple Health" is not true. Default: the setup card has the Strava row only, and the lede reads "Fitness reads workouts from Strava. Once connected, the nightly job pulls the last year, links each workout to a Health skill, and the coach starts proposing plan changes for your review." Wiring the webhook to `fitness.body_metric` is an integration folder change and its own task. Alternative: draw the row without a button, meta "NOT WIRED YET".
- XP column and "+36 XP HEALTH": XP per event is `skills.xp_weight` x link weight x confidence, and Fitness reads no other module's schema; core has no XP seam (`core.xp_weights` moved to `skills` in the skills migration). Default: no XP column (the table is DATE, WORKOUT, TIME, SKILL) and the This week sub-line reads "3H 42M · LOAD 277" (the app's crude load, which loses its own tile). The Skill Tree screen already lists the XP each workout earned. Alternative: an `xpFor(eventType)` seam on the module contract, a core change.
- The importing screen: the app's import is one server action over one job with no progress feed; "List activities · 212 found", "Fetch streams (HR, pace)" (the app reads average heart rate off the summary and fetches no streams) and "Classify to skills · rules 198 · model 14" are not reportable. Default: no importing screen; "Run first import →" pulses "Importing" while pending (as SyncBand's "Syncing") and the page re-renders live when the job returns. Alternative: a one-step block ("Pulling workouts from Strava" with "since {date} · running…" and an indeterminate bar) inside the card while pending.
- "CONNECTED · athlete 84121907 · 212 workouts found": the app knows neither before the import. Default: the green line reads "CONNECTED · {last_test_detail}" when Settings has tested the token ("Connected as Nick Comeaux."), "CONNECTED" alone otherwise.
- The tabs: the artboard draws only the workout list; the app has Exercises, Body and Plan tabs (the plan and coach are SPEC section 3, built as the follow-on pass). Default: keep the four URL tabs on the shared TabBar under the strip; the Workouts tab is the artboard's Recent workouts card (every row `listWorkouts` returns, 40, not the artboard's five); the other three tabs keep their lists as they are. Alternative: drop the tabs and stack Plan and Body as cards under the workouts.
- "Squat · best set": the artboard pins one lift; the app has no featured lift setting. Default: the heaviest set on file (by weight then reps, the README's rule), the lift named in the eyebrow ("Leg press · best set", "360 ×10", "YESTERDAY · LOWER"). The Heaviest set tile is therefore this tile in the artboard's shape.
- "Deadlift goal": Fitness reads no goals table. Default: through `getDigest('goals')` (the seam Health already uses for Insurance), the worst-status goal in the digest's `attention` list whose registry entity shares a skill link with any Fitness workout (one query over `core.entities` and `core.skill_links`, no skill id hard coded), drawn as "{current} / {target}" in the status colour (stalled red, at risk amber, on track green, the Goals tile's tones) over "{STATUS} · {percent}%". The fixture gives "340 / 405" and "STALLED · 50%" (the app's percent is start to target, the artboard's 84% is current over target). No such goal: "--" over "NO FITNESS GOAL". The tile's eyebrow is the goal's title.
- Body metrics tile: the artboard's copy ("WAITING FOR FIRST PAYLOAD", "APPLE HEALTH NOT CONNECTED") is about a source the app does not have. Default: "{lb}" with a 14px "lb" over "MEASURED {MON DD}" from the latest weight, "--" over "NO READINGS YET" when there is none; the eyebrow stays "Body metrics". `metrics.body_weight` on the manifest is untouched (Health reads it).
- The lede: the artboard's "First import done. Coaching proposals start after 7 days of data." names a rule the coach does not have (its rules are a layoff, a load jump, a stalled lift, a short week; no seven day gate). Default: "Workouts, what they came to, and the body metrics behind them. The coach reads the week and proposes plan changes into Review; nothing here changes the plan itself."
- Recent workouts meta: the artboard repeats the band ("STRAVA · SYNCED JUST NOW"). Default: the sources of the rows shown, "{n} STRAVA · {m} BY HAND" (manual, agent and demo count as by hand; zeros omitted; the fixture reads "10 BY HAND").
- Not drawn, no source: the hairline crosshairs on the card corners (a DS ornament), the row entrance animation, row hover (no row opens anything).
