# Notifications to the artboard

Superseded for styling on 2026-09-19 by the Holon redesign (docs/plans/holon-product-redesign.md, section 4): colour, type, radii, surfaces and control shapes now come from the Holon design contract and the shared components in `components/pos/`. This plan still governs what each screen shows and how it is laid out.


## Context

This is a core screen (not a module), already closer to the artboard than most: the band, the schedule card, the rules table with its expander, the alert centre and its history, and the preview rail all exist with the right bones, and the fourteen seeded rules (`supabase/migrations/20260908232600_core_notification_rules.sql`) match the artboard's `RULES` array module for module, key for key, and copy for copy. What differs is mostly surface: separators (the artboard joins every generated string with "·"; the app mixes "/" and "to"), a module colour on the rules table the app has flattened to one green, three small honesty gaps in the preview rail, and one shared-component ceiling. Two things the app already gets right and the plan does not touch: the morning digest field is a computed, non-editable display (`nightlyRunAt`) where the artboard shows a live time input, because the digest time is the Vercel cron and no field here could move it; and every header/page button stays sentence case (Button.tsx's own comment: "the tracked uppercase treatment is reserved for the theme toggle", which lives in the sidebar, not this screen) where the artboard's "Pause all" reads uppercase-tracked like its own theme toggle. Neither is chased.

Decisions with Nick (append to `decisions/log.md`):
- The alert centre's "via" column: the artboard's demo feed shows `SYSTEM · PUSH + EMAIL` for one alert (a single logical notification credited to two channels). `core.notifications.channel` is one column, not a set, and the seed inserts one row per channel a rule actually used, so the app has never been able to draw a combined label, `Alert.channel` is always singular. Default: keep one channel per alert row, as today (`alert.channel.replace('inapp', 'in-app').toUpperCase()`). Alternative: a `core/notify.ts` change (plus `core.notifications`) to record every channel a send went out on for one logical alert, so the row can join them (Blocked, core).
- The email preview's recipient: Rules.tsx hardcodes `pos@cmxlogic.com` (Preview, line ~490 of the current file) as `{{ digestSubject }}`'s address, which is not read from anywhere and is not necessarily true (the real recipient is `settings.digest_email` or `OWNER_EMAIL`, and either can be empty). Default: `app/(app)/settings/page.tsx` already reads `process.env.OWNER_EMAIL` server side for display, so `page.tsx` does the same: pass `digestEmail: settings.digest_email || process.env.OWNER_EMAIL || 'not set'` through `schedule`, and Rules.tsx renders that instead of the literal string. Alternative: leave the placeholder (rejected, it is not true for a fresh fork with no `OWNER_EMAIL` set).
- The email digest footer: the artboard's populated state reads "Batched from {n} rules. Reply STOP to any line to mute that rule." Resend is outbound only here; nothing in this app parses a reply. Default: keep the app's own footer, already true ("Batched from {n} rules. Mute a rule to drop it from this digest."); do not adopt "Reply STOP".
- The digest-empty widget ("NOTHING BATCHED") renders at 18px in the artboard's inline markup, but the shared `EmptyState` (`components/pos/EmptyState.tsx`, out of scope) fixes its headline at 22px, the same component the Alert Centre's "Inbox zero" already uses at 22px, matching the artboard's 22px there. Default: keep 22px for both (one size, used twice, consistent with itself). Alternative: a size prop on `EmptyState` (Blocked, components/pos).
